# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`AGENTS.md` holds the architecture invariants and editing boundaries (content-hash identity, reindex transaction, local-only assets, no auth). Read it first; this file only adds what it omits. `README.md` documents CLI flags, env vars, and HTTP routes.

## Commands

We use `just` for consistent local automation, backed by `uv` and `npm`:

```bash
just ci                         # Complete quality gate: Python check/test + Frontend check/test/build
just check                      # Run all linters and typecheckers (Ruff + Mypy + ESLint + TypeScript)
just test                       # Run all test suites (pytest + vitest)
just fmt                        # Auto-format codebase (ruff format + autofix)
just run                        # Start local book-reader server on :8000
just dev-ui                     # Vite dev server on :5173 (proxies backend routes to 127.0.0.1:8000)
just eval-offline               # Run Ask + OpenUI eval suite
just gen-prompt                 # Regenerate the OpenUI system prompt from the frontend library
just check-prompt               # Fail if the committed OpenUI prompt is stale (part of ci)
just eval-live                  # Run Ask eval live against inception:mercury-3
just benchmark-rag              # Benchmark retrieval against local library
just vendor-pdfjs               # Vendor PDF.js
just vendor-katex               # Vendor KaTeX

# Direct tool commands (when running without just):
uv run pytest -q
uv run pytest tests/reindex/test_reindex.py::test_name -q   # single test
cd frontend && npx vitest run src/ui/Button.test.tsx # single frontend test
uv run book-reader --reindex              # one-shot content-hash reindex, then exit
uv run book-reader --index                # build Elasticsearch index, then exit
scripts/build_frontend.sh                 # npm ci + vite build -> src/book_reader/static/app (gitignored)
```

- Ruff line length is 100; mypy is `strict` (relaxed only for `reading/pdf.py` and a few test modules, see `pyproject.toml`).
- Dev dependency group already includes `pageindex` and the LangChain/LangGraph stack, so the full suite runs after plain `uv sync`.
- `.env` is gitignored and loaded automatically at startup; `.env.example` is the template.
- The UI is a React SPA in `frontend/`. Edit SPA code under `frontend/src/`; `static/app/` is build output (gitignored), never hand-edit it. Needs Node 22 and npm. `static/vendor/` is generated by `scripts/vendor_pdfjs.py` / `scripts/vendor_katex.py`; do not hand-edit it, and do not bundle PDF.js/KaTeX through npm.

## Architecture notes (beyond AGENTS.md)

- Backend layout is feature-first (ADR-009): `state/` (process lock, `remap.py`, preferences), `library/` (`scan.py`, `models.py`, `errors.py`), `reading/` (`pdf`, `markdown`, `pages`, `progress`, `sections`), `notes/`, `search/`, `chat/`, `organize/`, `reindex/`, and `api/` (errors, security, static, views, `routes/`). Domain packages never import `fastapi`; they raise domain errors (`InvalidPath`, `PathNotFound`, `UnknownModel`) that `api/errors.py` maps to 400/404.
- `services.py` (`Services` + `build_services`) is the composition root: it constructs every store and service, all sharing one `threading.RLock` (the "state lock"). `app.py` (`create_app`) takes the cross-process `StateDirectoryLock` (flock on `.book-reader.lock`), runs the startup reindex and registers routes. Every module in `api/routes/` exposes `register(app, **deps)` (explicit keyword dependencies, not the `Services` object). New routes belong in `api/routes/`, not in `app.py`.
- `library/scan.py` is the single path-safety choke point: every route that takes a `rel` path from the client must resolve it through `Library` (`book_file`, `find_book`, `any_file`), never `Path(root) / rel`.
- Stores are plain-JSON files in the state dir, keyed by content hash where portable (`progress`, `notepad`, `pages`, `sections`, `categories`, `chats`). When touching a store's key scheme, update `reindex/reconciler.py` and `state/remap.py` so reindex remaps it, and add it to the backup list. Stores never import `reindex/`.
- Chat/RAG lives in `chat/`. Langchain-free modules: `types.py`, `providers.py`, `config.py` (request limits, model selection), `sessions.py` (`ChatStore`: persistence/retention, history with `thought_steps: list[str]`), `registry.py`. Langchain-backed: `service.py` (provider fallback chain), `graph.py` (LangGraph agent, bounded tool rounds, thought streaming), `tools.py` (`search_library`/`read_document`/`add_note`, step tracking), `model.py`, `prompts.py`, `sources.py`, `context.py`. `langchain`/`langgraph` are optional extras, so `chat/__init__.py` is empty and `chat.service` is imported lazily (inside functions, behind `TYPE_CHECKING` in `services.py`); keep them that way.
- Chat Options & Preferences: `GET /api/chat/options` and `POST /api/chat/options` expose active model and reasoning effort (`low`, `medium`, `high`, `default`). The frontend `ModelEffortBar` allows instant switching in both `/ask` and reader rail.
- Live Process & Thought Streaming: `api/routes/chat_sessions.py` emits SSE events: `step`, `found` (cumulative documents the tools returned, via `AskCallbacks.on_found`), `thought`, `delta`, `done`, `error`. The POST blocks until the answer is done, so `useAskData` subscribes while `sending` (not only when the cached status is `thinking`). Active execution is rendered by `ProcessCard.tsx` and finalized with a collapsible `.thoughtTrace` (`ChatMessageView.tsx`).
- Resizable Rails: `frontend/src/ui/useRailResize.ts` supports dragging side-rails (Ask, TOC) up to 50% of the viewport width.
- Chat visual blocks use OpenUI Lang. `frontend/src/features/chat-render/openui/library.tsx` (Zod-typed `defineComponent`s) is the source of truth; `npm run gen:openui-prompt` writes `src/book_reader/prompts/openui_prompt.txt` + `.spec.json` (committed; `scripts/check_openui_prompt.sh` fails CI when stale). `chat/prompts.py` loads that text; `BOOK_READER_OPENUI_FORMAT=lang|json` picks what the model is asked to write; `json` is the default because `lang` failed the live-model gate (ADR-008), but the frontend renders both. Prop key order in a Zod schema is the positional argument order, so reordering props changes the wire format. `legacyJson.ts` only exists to render chats stored before the migration. `@openuidev/*` are installed with `ignore-scripts` (`frontend/.npmrc`): `lang-core` ships a telemetry postinstall.
- Model registry: `src/book_reader/chat/models.json` (+ `chat/registry.py`) records per `provider:model` whether it accepts `reasoning_effort` and which OpenUI format it follows (`json` unless its live eval supports `lang`; `tests/chat/test_models.py` enforces that and that every default-priority model is registered). `chat/service.py` uses it to skip `reasoning_effort` for models that reject it and to pick the prompt format per model; `BOOK_READER_OPENUI_FORMAT` overrides it. Add an entry whenever a model joins `DEFAULT_PRIORITY`. Replay saved live answers through the real renderer with `eval_ask.py --live --save-answers F` + `OPENUI_REPLAY=F npx vitest run src/features/chat-render/replay.test.tsx`.
- Search is layered in `search/` (`service.py` picks the backend): Elasticsearch BM25 (`elastic.py`) → PageIndex section trees (`pageindex.py`, `reading/sections.py`) → in-process scan. Backend choice follows `--search auto|elastic|pageindex|local`; every path must degrade when Elasticsearch or PageIndex is absent.
- PDF rendering is native React 19 via `react-pdf` v11 (`frontend/src/features/reader-pdf/`, `ADR-007`), using windowed canvas virtualization (`isPageRendered`), an integrated toolbar (`PdfToolbar`), left-docked outline and thumbnail rail (`PdfContentsRail`), in-document text search (`usePdfSearch`), `#p12` deep links, selection → note capture, and `BookContext` synchronization.
- `api/routes/spa.py` (`register(app, *, library, reconciler, spa_dir)`) serves the SPA shell for `/`, `/ask`, `/design`, `/book/{rel}`. `create_app(..., static_dir=)` is the test seam for a packaged bundle.
- `frontend/src/`: `app/` shell and routes, `features/<name>/` one folder per page or rail (including `chat-model/`, `ask/`, `chat-rail/`, `chat-render/`), `ui/` primitives (`/design` is the development-only kitchen sink), `styles/tokens.css` design tokens, `api/` fetch client and types.
- UI libraries in `frontend/`: `@base-ui/react` (unstyled a11y primitives — Button, Dialog, Select, Tabs, Menu — wrapped in `ui/` and styled with CSS Modules + tokens; portal setup in `styles/reset.css`), beautiful-ui primitives (MIT, `slev12397/beautiful-ui`) ported into `features/chat-render/agent/` (AgentTrace ← ThinkingState, TaskRows, ContextCards, PromptBar), `react-pdf` v11 + vendored pdfjs-dist 6.x for the reader, vendored KaTeX 0.19.1 for math, `@tanstack/react-query` (server state), `react-router-dom` v7, `zod`, `@openuidev/react-lang` (OpenUI blocks, `ignore-scripts`), `@radix-ui/react-toast` + `@radix-ui/react-visually-hidden`. See DESIGN.md for the Ask design layers.

## Testing

- `tests/conftest.py` provides `library` (tmp PDF + Markdown tree built with PyMuPDF), `spa_static` (minimal packaged SPA) and `client` (`TestClient` over `create_app(library, state, static_dir=spa_static)` with a tmp state dir) fixtures; build new tests on them rather than touching a real library or state dir.
- Tests must not hit Elasticsearch or LLM providers; existing tests use small fake clients/providers (see `tests/search/test_retrieval.py`, `tests/chat/test_chat_sessions.py`); tests mirror the backend packages under `tests/<package>/`.
